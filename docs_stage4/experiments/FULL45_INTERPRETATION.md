# 两个固定独立测试锚点的离线完整参考网格检查

按指定case和时刻检查，没有选择有利状态：
`static3d_v01_s410001`及`crossing3d_v02_s410102`，均为B0实际执行到40秒的状态。
从初始化逐0.02秒重放全部历史控制，恢复完整控制器，再复现原9候选B0决策。
每条45网格参考只做一次完整24秒原REMUS前向预测，随后对同一候选、同一交付
历史计算B0/B1/B2；所有方法的决定先完成，之后才独立查询未来真值。

这里“真值可行”表示**该参考持续保持24秒**的反事实路径，对所有真实障碍和海床
以0.02秒物理扫掠检查后保持1米净间隙。它不等于真实闭环未来24秒的执行：
真实系统每2秒重新规划。“false reject”仅是相对实现的未来真值拒绝了安全
保持参考；校准的保守拒绝不因此自动成为程序错误。

static_v01的5条真值安全参考为索引33、36、39、42、43，原9短名单中已有39。

完全遗漏了所有真值安全参考。不能把这个保持参考碰撞误称为真实执行已经碰撞。

crossing_v02的全部45条参考在实现的真值下可行，B0原9选择30，预测净间隙
13.939米、保持参考真值净间隙14.545米；此处B0的5次false reject来自其预测
包络，而非车辆真的无法执行。

B1两状态的额外q均为63.041米；B2分别约29.608–42.829米、29.338–42.490米。
B2确实比同一校准库的B1半径小，但本次两锚点的45条参考仍全部被B1/B2拒绝。
因此，**在这两个固定B0状态下**把完整验证预算从9提高到45也不能产生B1/B2
认为可行的常规参考；q更小没有改变其零可行候选结论。
这不是对所有时间、所有场景或B1/B2自身闭环状态的证明。
