# 阶段4风险方法最小可行性实验协议

本协议在三方法闭环成绩产生前固定。实现为
`auv3d/stage4_protocol.py`，`manifest()` 返回48个完整场景，
`config_for_case()` 对任何方法返回相同的 `Stage2Config`。
风险选择是独立方法设置，不允许藏在场景参数中。

## 共同平台与方法范围

REMUS 100原水动力学、控制器、执行器、物理限幅及初始化方法不变。
所有方法使用CA、原45个参考网格、diverse筛选、最多9个完整六自由度候选、
RPM0滑行应急、4秒硬过期记忆、24秒预测时域、2秒规划周期、0.02秒物理步长。
所有场景共同使用已有普通粗网格三维A*海床引导；规划实际仍读取真实REMUS状态。
任务时间上限200秒、到达半径5米、净安全裕量1米、原扫掠球碰撞监视保持不变。
三方法预测历史重采样间隔共同为1秒。

| 方法 | 共同CA预测之外的风险处理 |
| --- | --- |
| B0 | 原0.75米固定预测裕量，加原观测年龄及感知记忆项 |
| B1 | 保留B0各项，再加本轮独立数据校准的P25式误差球 |
| B2 | 保留B0各项，再加借鉴ECP的候选轨迹相关风险校准项 |

B1/B2校准项是额外预测包络，不能缩小物理球、修改真实障碍半径或降低1米标准。
B2借鉴 [ECP-MPC作者实现](https://github.com/CORE-SNU/ECP-MPC)，
不将ECP既有原理称为原创。本轮是冻结的离线ECP适配，不实现ACP在线自适应，
不替换REMUS为二维行人模型，不增加学习网络。

## 完整场景划分

六个原场景族各8个预登记变体。每族1个train、1个tune、4个calibration、
2个test，合计36个开发场景及12个独立测试场景。
同一场景的历史、未来窗口、障碍对象及完整执行结果不能跨split。

| 场景族 | train索引 | tune索引 | calibration索引 | test索引 |
| --- | --- | --- | --- | --- |
| static3d | 2 | 4 | 0,3,5,7 | 1,6 |
| crossing3d | 0 | 5 | 1,3,4,6 | 2,7 |
| maneuvering3d | 1 | 6 | 0,2,5,7 | 3,4 |
| multi_crossing3d | 7 | 2 | 1,3,4,6 | 0,5 |
| terrain3d | 3 | 1 | 0,2,5,7 | 4,6 |
| perlin_cruise_constrained3d | 5 | 0 | 1,2,4,6 | 3,7 |

完整场景划分防止重叠窗口泄漏，**不会自动证明这些固定、分层场景交换性**。
这是合成场景下的配对可行性试验，不是总体闭环碰撞概率认证。
大量同场景窗口是相关数据，不作为大量独立conformal样本计数。

## 真正变化的场景条件

受控场景的障碍位置和运动公式保持原实现。其`seed`并不改变物理几何，
因此不能仅将同一无噪场景换seed计作多个独立场景。
本协议预登记实际参数变化，且对三方法完全共享。

下表中的条目按变体索引0至7排列；动态场景及静态场景共同使用0.02米标准差的
原有独立高斯位置测量噪声。它是公开的合成传感假设，不是硬件声呐标定结果。

| 场景族 | 8个预登记变体 |
| --- | --- |
| static3d | `(海流m/s,方向°,观测延迟s)`：`(0,90,0),(0.1,45,0),(0.1,90,1),(0.1,135,0),(0.15,90,1),(0.15,270,0),(0.2,45,0),(0.2,135,1)` |
| crossing3d | `(障碍速度倍率,观测周期s,延迟s)`：`(1,1,0),(0.75,1,1),(1.25,1,0),(1.5,1,1),(1,2,0),(0.75,2,1),(1.25,2,1),(1.5,2,0)` |
| maneuvering3d | `(速度倍率,转率参数°/s)`：`(0.8,4),(1,4),(1.2,4),(1.4,4),(0.8,8),(1,8),(1.2,8),(1.4,8)` |
| multi_crossing3d | `(速度倍率,垂直FOV°,观测周期s,延迟s)`：`(1,30,1,0),(0.8,6,1,0),(1.2,30,2,1),(1.5,30,1,0),(1,6,2,0),(0.8,30,2,1),(1.2,6,1,1),(1.5,6,2,1)` |
| terrain3d | 原山脊公式的幅值米：`40,45,50,55,60,65,70,75` |
| perlin_cruise_constrained3d | 真正改变原Perlin海床的固定种子：`7,11,13,17,19,23,29,31` |

非Perlin观测种子为`410000 + 100×场景族索引 + 变体索引`。
Perlin仍采用阶段3既有的几何顺序与原REMUS固定24秒中性巡航初始化准入，
不使用风险方法、DWA成绩或预测器结果选择起终点，不重试有利种子。
这种准入只验证初始化24秒，不能证明全任务可达。

窄视场、观测间隔和延迟提供短暂失联条件；必须报告真实日志中的失联、
删除和重捕获数据，不能把“可能失联”写成已经实现某个固定时长遮挡。
原4秒硬删除造成的彻底不可见目标是共同感知限制，风险方法不能凭空恢复目标。

两个海床场景族都没有动态障碍，因此是风险处理的负对照：
三方法应保留同一A*引导和实际执行轨迹，不把纯地形成功归因于ECP。

## 校准数据、时间与冻结规则

train仅用于数据、特征和接口开发，CA没有拟合权重。
校准数据来自24个calibration场景的共同B0实际闭环：保存真正交付的历史，
离线将同一障碍生成器推进到锚点加24秒得到合成真值标签，形成误差轨迹库。
不另换更宽视场、更少延迟或理想轨迹生成有利校准数据。
B1和B2使用同一库，按已观测ego航向进行刚体对齐。
如果B0提前到达、碰撞或终止，之后的标签属于原障碍模型继续运动的反事实区间，
不是在线曾交付的未来观测；这些离线标签不能回流成为在线ACP更新。

预报以REMUS规划绝对时间为锚点，覆盖24秒，库采样间隔0.2秒。
每个完整场景将其成熟锚点与预测区间分数取最大，得到scene级分数；
最终候选验证仍覆盖每个0.02秒物理区间。
不将阶段1已有9秒校准表静默外推成24秒校准。
任何尚未成熟、尚未交付、超出库支持范围的标签不得用于在线风险评分。
真值仅用于离线校准、事后评价、实际碰撞监视及绘图，不能进入候选选择。

24个calibration场景中，两个无障碍地形族占8个，只有16个场景可能提供障碍误差轨迹。
若无障碍场景分数定义为0，所得阈值对应整个混合场景目标分布，
不能宣称条件于出现障碍时有同等覆盖率。报告须同时列出总校准场景数、
有标签场景数、空场景数和每场景窗口数；校准覆盖必须说明评价单位。

预登记风险水平为`alpha = 0.1, 0.2, 0.3`，在独立tune集报告全部安全—效率曲线。
独立test统一固定`alpha=0.1`，即使tune不支持收益也先进行诚实诊断，
不得按test结果再挑阈值。B0没有校准alpha，应复用同一B0结果，不能重复计样本数。

## 配对评价与失败保留

每个方法使用同一case、同一种子、同一原始真实障碍运动、同一感知配置、
同一CA预测和计算预算。闭环后轨迹变化会改变视场及后续观测，
这是控制影响感知的真实反馈，不能伪造三方法始终收到完全相同位置观测。
原`IdealObjectSonar`按可见对象顺序消费同种子随机数；不同航迹导致可见对象数
改变后，后续同一对象时刻的噪声抽样也可能不再逐项相同。
本轮保持原感知接口和已登记数据，结论限定为共同种子、噪声分布及接口的配对实验，
不能声称全过程完全相同的噪声场。正式扩大研究时可预先固定按对象和观测时刻
索引的噪声场，但不能事后换掉当前B0数据。
归因时应同时检查同一真实REMUS状态/同一交付历史下的候选动作差异，
以及最终真实闭环是否改善。

逐场景记录限时到达、碰撞、实际1米裕量违反、危险应急、无可行候选、
候选误判、校准覆盖、P95规划耗时及超2秒周期次数。规划墙钟耗时按原同步离线语义统计，
不暗称已经加入物理计算延迟。未到达、碰撞及低裕量案例全部保留，
不剔除失败后声称节能或提高成功率。

工厂或初始化准入异常必须记录在原case ID，不替换种子或场景。
有限时域危险应急与实际碰撞是不同指标；到达不等于满足安全裕量。

## 已实际执行的预检

2026-10-12本地执行48个原场景工厂、起终点合法性检查，以及16个海床场景的
原A*几何路线检查，48/48完成、0程序异常，墙钟8.756秒。
8个Perlin场景的海床数组两两不同，全部通过原有固定24秒初始化巡航准入，
没有更换种子；其准入最小净间隙约为
`29.194,7.621,2.518,29.194,29.194,29.194,29.194,20.082`米。
这些数字是初始化准入结果，**不是闭环任务成功结果**。

协议模块测试实际69/69通过。原始预检、seed不变性检查和测试日志保存于
`results_stage4/protocol_review_20261012/`。
工厂预检不会替代B0/B1/B2闭环实验，也不会证明ECP具有收益。

## 同状态归因与反事实误判检查

`auv3d/stage4_diagnostics.py`从原`initialize_plant`开始，按保存参考每0.02秒
调用原控制器和动力学，核对全部实际状态、原始/施加舵面请求及执行器状态，
恢复完整控制器积分与参考动态。不能仅从姿态CSV猜测控制器状态。
固定20、40、60秒且存在已交付目标的锚点用于同状态B0/B1/B2对照；
没有目标或已经结束的时刻不替换为更有利时刻。候选规划仅接收独立plant克隆、
交付历史、原规划子目标、上一选中参考及原记忆不确定性。

只有候选决定已经产生后，独立`OfflineTruthReplay`才使用未来真值。
它将选中参考保持完整24秒，以相同物理扫掠碰撞几何评估所有真实目标，
包括当时不可见目标，并另外评估已观测目标的ECP最近对象间隙分数和球误差。
`selected_forecast_false_feasible`只说明这条选中参考被预测可行而其反事实
整时域未维持1米净间隙；不能将它称为所有候选误判率或实际闭环碰撞。
下一周期重规划后的真实执行也不等于继续保持该参考24秒。
覆盖诊断使用0.02秒物理采样，比0.2秒校准库支持点更密，须注明评价网格。
无已观测对象时误差与覆盖记为未定义，不能用零误差冒充覆盖成功。

模块已对本轮`crossing3d_v04_s410104`实际记录执行核验：6544个实际状态和
6543个控制区间全部重放匹配，20、40、60秒三帧的B0同状态动作、可行判断和
预测净间隙均重现，之后才执行未来真值诊断，墙钟6.175秒。
证据为`controller_replay_actual_case.json`。协议与诊断合计89/89测试通过，
包括原控制器隔离、时钟、因果交付、日志损坏拒绝和多人ECP间隙核一致性。
