# P25 三维规划与 REMUS 六自由度接口核对

本次整合保留两个明确区分的运行后端。`run_remus.py` 与 `auv3d.remus.RemusPlant` 使用仓库原有 `PythonVehicleSimulator` 六自由度模型；`run_stage1.py simulate --scenario ...` 的 `empty3d`、`static3d`、`crossing3d`、`paper_random3d` 使用 P25 简化三维运动学。后者的“执行轨迹”是简化运动学积分结果，不能标为 REMUS 六自由度实际执行轨迹。

`route_demo()` 通过深度、航向、RPM 参考值实现六自由度三维航点跟踪。它没有调用 DWA、预测器、障碍碰撞约束或安全回退策略，因而不代表六自由度闭环避障。

## 状态、动作与单位

| 项目 | P25 阶段 1 | REMUS 原模型 |
|---|---|---|
| 位置 | `state[:3] = [N, E, D]`，米 | `eta[:3] = [N, E, D]`，米 |
| 姿态 | `state[4:6] = [theta, psi]`，弧度；不模拟滚转 | `eta[3:6] = [phi, theta, psi]`，弧度 |
| 速度 | `state[3] = u`，米/秒；每次积分直接采用候选指令 | `nu[:3] = [u, v, w]`，本体坐标速度，米/秒；由水动力学产生 |
| 角速度 | 候选动作 `[u, q, r]` 中 `q, r` 为弧度/秒 | `nu[3:6] = [p, q, r]` 为本体角速度，弧度/秒 |
| 原始执行器命令 | 无舵、螺旋桨和执行器时滞 | `[delta_r, delta_s, n]` = 方向舵弧度、升降舵弧度、RPM |
| 自动驾驶参考 | 阶段 1 DWA 不产生这些参考 | `ref_z` 米、`ref_psi` **度**、`ref_n` RPM |
| 洋流 | 可选 NED 速度在位置导数中加一次，默认零 | 原模型支持固定水平洋流；动力学内部计算相对水速，位置积分直接用 `Rzyx @ nu[:3]` |

统一使用 NED：深度 `D` 向下为正，正俯仰表示抬头。在零滚转、正前进速度下，`D_dot = -u sin(theta)`；绘图的深度轴必须倒置以使海底位于海面下方。

P25 的公式在 `auv3d/geometry.py::kinematic_derivative` 中实现：

```text
N_dot = u cos(psi) cos(theta)
E_dot = u sin(psi) cos(theta)
D_dot = -u sin(theta)
theta_dot = q
psi_dot = r / cos(theta)
```

这里的 `r` 不是欧拉航向角速度。REMUS 用完整的 `Tzyx(phi, theta)` 将 `[p,q,r]` 转为欧拉角速度：

```text
theta_dot = q cos(phi) - r sin(phi)
psi_dot   = (q sin(phi) + r cos(phi)) / cos(theta)
```

零滚转时这两式才具有 P25 的形式；简化模型也没有模拟滚转动力学及保持零滚转所需的约束。因此不能直接将候选 `q/r` 当作舵角、航向参考，或对一般六自由度姿态按 P25 方式积分。源码测试保留了正俯仰/NED 关系以及非零滚转下的角速率转换检查。

## 保留的物理参数与普通接口检查

唯一模型来源为 `PythonVehicleSimulator/src/python_vehicle_simulator`。适配器采用正常 Python 包导入，并检查模块的实际来源路径；不使用 `third_party/pvs_minimal`，也不动态改写原模型。`verify_sources()` 仅为兼容既有调用保留名称，其内容只是必需文件存在性检查；不比较文件内容或源码身份。

模型加载还检查 `dynamics`、`depthHeadingAutopilot`、坐标变换函数是否存在，`nu`/`u_actual`/质量矩阵维度是否合法，参数是否有限且为正，质量矩阵是否对称正定。普通源码注释修改不会阻止运行；实际接口或数值参数不合法会给出明确异常。

原源码保留的约束包括：深度参考 0–100 米、最大 RPM 1525、舵面幅值 15 度、舵机时间常数 0.1 秒、螺旋桨时间常数 1 秒。质量由原源码中的几何尺寸和密度计算，约 31.0294 千克；源码注释的 31.9 千克不是修改质量矩阵的依据。P25 动态障碍的加速度、角速率和控制增益只应用于障碍物。

`RemusPlant.step()` 保留原有 0.02 秒或更小的积分步长约束，检查非有限状态和接近欧拉奇异姿态。原回归使用未经适配器裁剪的原自动驾驶命令；航点演示可显式选择舵面请求裁剪。两者均不修改水动力学和执行器参数。

## 候选指令与真实可执行能力的差距

`auv3d/config.py::VehicleConfig` 中 2.5 米/秒、0.3 米/秒²、俯仰率 4 度/秒、偏航率 5 度/秒等是当前规划开发设置。它们不是由 REMUS 动力学辨识得到的完整可达集合。DWA 允许即时设置速度和角速率，REMUS 则受推力、惯性、阻尼、舵面限幅及执行器时滞影响；相同的 `[u,q,r]` 未必能在下一个控制周期实现。

`auv3d.remus.characterize()` 可以生成不同 RPM、转向、变深及横流工况的瞬态数据。其统计量是特定工作点的模型响应，不代表物理最大机动能力，也不能单独作为安全保证。

## 后续完整六自由度动态避障接口清单

1. 在新增独立适配模块（建议 `auv3d/adapters/remus_guidance.py`）中，将真实 `eta/nu` 投影到规划状态，并明确选择对水速度或对地速度；对非零滚转和侧滑进行处理。保持原 `remus100.py` 不变。
2. 将规划 `[u,q,r]` 转换成可执行的深度、航向、RPM 参考或受约束的执行器指令。需要基于工况数据建立速度到 RPM 的映射，并处理参考滤波、航向展开、积分饱和及舵机时滞。
3. 在 `auv3d/planner.py::rollout` 旁增加独立 REMUS 候选预测后端。每个候选必须隔离复制车辆、自动驾驶积分器和执行器状态，避免候选仿真污染实际车辆；验证预测误差并增加经过测量的跟踪裕量。
4. 在 `auv3d/simulation.py::run_episode` 对应的新六自由度执行循环中，以 0.02 秒动力学步长执行指令，以配置周期调用 DWA 和传感器。真实传感器姿态需要完整 `[N,E,D,phi,theta,psi]`，不能固定滚转为零。
5. 用实际六自由度轨迹与同一时间段内的动态障碍位置执行扫掠碰撞检查；保留当前碰撞标准。对失去可行候选、过期观测和跟踪偏差设置可验证的处理策略，并评估洋流下无法瞬停的情形。
6. 记录并分别绘制 DWA 预测轨迹、真实 REMUS 执行轨迹、执行器指令/实际值、跟踪误差和失败原因。增加完整无障碍、静态障碍、动态交叉、随机地形的闭环回归后，才可以声称完成六自由度闭环避障。

本次合并未实现上述新闭环接口；已存在的 REMUS 航点演示和 P25 避障保持各自真实功能。
