# 阶段2修改记录

本阶段在原AUVWorkPlace内建立参考空间DWA—原REMUS六自由度闭环工程基线。真实执行状态来自 `RemusPlant`，候选和真实执行使用同一份原水动力模型。没有实现ECP、强化学习或新论文算法。

## 保护的既有内容

`PythonVehicleSimulator/` 保持唯一REMUS实现；未修改质量、惯性、阻尼、舵面、推进器、执行器时间常数或原自动驾驶参数。`run_remus.py`、`run_remus.cmd`、`requirements-lock.txt`、阶段1入口、已训练权重、历史结果和原147项测试保留。独立阶段2依赖环境复用阶段1核心清单，不要求GPU。

阶段1 `auv3d/planner.py`、`simulation.py` 的原P25入口继续可用。第二阶段P25对照复用它的运动学和规划器，不能替代REMUS实际执行。阶段1接口文档保留为历史资料，README已指向本阶段现状。

## 开发修正与边界

最初12秒时域在静态场景超时并频繁应急，迎面场景发生碰撞。原航向/深度参考动态较慢，需要更早考虑动作后果；统一默认时域改为24秒，保留原失败记录。没有改变场景几何、碰撞标准或原车辆参数。默认每次完整验证最多9个候选，无可行候选时额外验证1个RPM0参考；候选网格没有穷举最优或全局可达性保证。

RPM0是减小推进参考，原执行器和车辆会继续运动。应急的预测净间隙、安全判断和实际事件均保存；不可行情况下不宣布安全停止。动态障碍预测只从已交付观测生成，不使用场景未来运动。原水动力学的航向差海流近似保留，完整三维速度坐标转换另行明确，位置积分不重复加流。

到达结局与安全验收独立记录：不安全应急或实际间隙低于配置余量都会使 `avoidance_acceptance_passed` 为假，即使 `reached_goal` 为真。早期正式输出保留原样，最终报告根据原始事件/间隙补充同一判定。同步离线计算暂未把规划墙钟耗时注入物理执行时钟。

共享P25入口的24秒时域会使原批量候选在合法性筛选前穿过欧拉奇异点；新增局部适配器先按当前俯仰与时域筛除超出原±30度的候选，保留原运动学、评分和碰撞条件。初次错误日志和修复后实测都保留；原9秒入口候选结果的一致性有回归测试。

结束时补存仅用于显示的障碍真值快照，使GIF与HTML显示实际到达/碰撞末点。旧正式crossing输出不改写，在独立 `visuals_final/crossing3d` 重绘并记录终点修正与逐快照核对。

阶段2使用CA障碍预测和披露的确定性余量。原PPLNM的三步/9秒预测不能自动延展为24秒可信预测，本阶段REMUS入口不加载该权重。P25共享场景对照不同车辆模型、参考动作和初始速度，不作为只比较规划算法的公平成功率实验。

## 输出与证据

新运行写入独立 `results_stage2/`，非空目录拒绝覆盖。保存原始实际状态、参考命令、原控制器请求、裁剪后命令、实际执行器、候选计数与时间、选中预测、观测时间障碍快照、实际近距交互、应急/碰撞事件和最终原因。

`states.csv` 在物理时刻记录实际状态；`controls.csv` 的 `time_s` 是控制积分区间起点，参考和命令用于该区间，其实际执行器字段是区间末值；`prediction_errors.csv` 使用区间末时刻与相应预测点比较。内存中的候选验证保留全部物理积分点；保存的 `selected_plans.json` 按配置的显示间隔稀疏化，只用于展示和分析，不替代碰撞检查。

具体全量测试数、命令、状态、最小间隙、规划P95及真实失败以 [TEST_REPORT.md](TEST_REPORT.md) 为准。已实际执行的独立响应与诊断见 [SCENARIOS.md](SCENARIOS.md)。同一确定性模型、完整初态和保持参考时的零误差证明数值重放与隔离正确，不是实际AUV执行误差或安全性的证明。
