# 后续ECP与执行误差接口清单

本阶段已建立真实REMUS六自由度状态反馈、参考动作采样、候选完整模型验证和真实执行碰撞监视。以下是后续研究的具体接入位置；本阶段没有ECP实现，也没有声称对实艇安全或不可观测未来障碍运动提供保证。

## 现有闭环合同

1. `RemusPlant` 持有原车辆的实际位姿、绝对体坐标速度、实际执行器、控制器积分和参考模型状态。`RemusGuidance.step` 把目标深度/航向/RPM交给原自动驾驶控制器，随后调用原动力学一次。
2. `candidate_references` 采样 `ReferenceAction(depth_m, heading_rad, rpm)`；P25的 `[u,q,r]` 只在简化后端使用，不能作为实际舵角。
3. `_fast_rollouts` 仅用于排序；`predict_reference` 对完全隔离的车辆状态做完整六自由度积分，所有安全接受候选均经过该步骤。
4. `_forecast_tracks` 从因果观测历史产生CA障碍预测；`trajectory_clearance` 使用预测障碍及完整候选物理轨迹做时间对齐扫掠和保守地形检查。
5. `run_remus_episode` 执行选中参考，按实际轨迹检查碰撞，下一规划周期读取新的真实状态。选中预测、实际状态、误差、延迟和应急信息独立保存。

当前障碍安全余量是工程常数与观测年龄函数，没有概率校准。完整REMUS前向预测是车辆动态模型验证；它不使CA障碍预测或稀疏传感器变成真实未来。

## 执行误差实验应保留的对照

先保留本阶段的原模型确定性重放：从同一完整状态克隆、固定同一参考、相同步长，预测和实际应数值一致。然后在实际执行包装器单独开启可控扰动，预测模型保持基准，逐项测量误差来源。若同时改变候选动作、障碍、感知和执行器，很难解释补偿收益。

原动力学保留航向差方式的水平海流近似。对于非零横滚/俯仰，完整几何相对速度使用 `nu[:3] - Rzyx.T @ current_NED`，与源模型的航向近似分别记录。绝对体坐标速度已经用于位置积分，不能再加海流。任何未来时变流扩展应通过独立外部接口并保留原恒定流对照，不能悄悄改变水动力参数。

P25共享场景有助于检查模型差异，但其初始对水速度1m/s、理想速率动作和REMUS预热巡航条件不同。研究算法收益时，应将各方法放在相同REMUS执行模型、初始化、观测和碰撞评价上；不要以P25成功率代表六自由度执行。

## 报告与后续验收

至少报告任务到达/碰撞/超时、失败原因、最小实际净间隙、应急次数与不安全应急预测次数、实际交互对象数、同时近距对象数、最大单次观测/跟踪数、规划中位数/P95/最大耗时及超控制周期次数。执行误差报告需要给出比较时间范围、保持参考或重规划条件、位置/深度/航向误差曲线和模型假设。

多种子和挑战场景中的失败必须保留；实时预算需由目标机器实测，不从仿真时钟推断。当前24秒预测、2秒规划周期与9候选预算是工程选择，不证明全局可达、最优或真实平台安全。未实现内容不能写成已通过项目。
